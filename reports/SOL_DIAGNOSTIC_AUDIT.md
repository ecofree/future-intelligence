## 2. 已定位的问题

1. **计划顺序没有约束领取。** 驱动按计划循环，但 run_once 仍按 task UUID 领取；还用计划中的 question_type/task_id 覆盖真实返回标签。更正说明与实际保存记录能恢复身份对应，原摘要和更正一起保留，不重写历史。0017 和 --task 使指定领取成为显式动作，结果保持真实身份。
2. **输入计数失败后仍发送。** 两次 `/responses/input_tokens` 返回 400/unknown_parameter/max_output_tokens，input_tokens 为空。驱动退回字节数加 4096；这不证明完整输入计数。新增六字段映射与回执校验，并接入受控 worker 的发送前门控；不能用后来的推理 usage 冒充事前计数。
3. **实际代码/函数不同于规范提交。** 附件驱动 monkeypatch 生成配置，并在迁移后覆盖 fi.valid_terra_generation、fi.native_entries_allowed，才能接受 Sol。迁移表停在 0016 不包含这些覆盖；校验和全部匹配也不证明安装后函数匹配。没有采纳这些覆盖或放宽 Terra 白名单。原库保留，后续须核验函数/ACL 指纹与覆盖脚本哈希。
4. **解析钩子未交接。** worker 进程通过 DoH 注入，宿主仍 fake-IP。包中缺 sitecustomize.py、其 SHA256、脱敏启动及 CA 配置。hook_loaded、公开 IP 摘要、官方 HTTP 200、TSA 302 都不等于宿主安全预检或生产信任通过；现有 SSRF/TLS 防护保留。
5. **首发整点被 +1µs 排除。** Sol 冻结题的 outcome_not_before 比公布时间晚 1 微秒。结果 guard 会拒绝真实整点 published_at，不能改官方时间来适配。0018 允许新题两个边界相等，同时严格执行预测/证明截止；旧题保留原值。
6. **完整条款尚未绑定核验。** 附件有主要常数/区间/首发策略，但未证明完整缺失、延后、版本冲突、内部错误、VOID 条款进入实际冻结对象。下一版本采用 ADR-022 v2 的完整规则或冻结引用的规则字节哈希，不能仅写 ADR 标识。

## 3. 预算核对

已登记推理未知预留：`0.14 + 0.30 + 0.13 + 0.13 = $0.70`。本次两题按全部输入缓存写入费率的参考估算为 $0.016965，不是账单，不释放 $0.26。

[OpenAI 官方帮助中心](https://help.openai.com/en/articles/4936856-understanding-and-counting-tokens) 于本次独立核验明确：输入计数接口免费、不消耗正常模型推理额度，后续生成请求另计费。因此不把附件自行预设的计数费用备用额度当作已经发生的支出；失败计数的记录和门槛仍保留。

运行方所述 $0.04 是 `.70 + 两次尚未发生的Sol FORMAL预留.26 = .96` 后的计划余量；实际尚未承诺额度为 $0.30。此计划不授权改用 Sol 或重试。

若继续原官方 Terra 目标，完整输入计数 ≤16384、max_output_tokens=8192、全输入按 $1.25/百万、输出 $5/百万、全球/default/无付费工具及适用报价均核验通过，单次上界 $0.061440，可在全新实验预留 $0.07。两题新诊断加两题新 FORMAL 的条件计划为 `.70 + 4×.07 = $0.98`。预算条件未通过时不派发；$0.02 不是重试授权。详见 [复测说明](../docs/OFFICIAL_TERRA_RETEST.md)。
