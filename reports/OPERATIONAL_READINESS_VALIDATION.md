## 本批实现

1. 新 LIVE 任务显式选择 FORMAL 或 DIAGNOSTIC；模式在第一次尝试/批次前固定，不得追溯升级。联调不能封存为正式计分批次。
2. CALENDAR/TARGET_STATUS 快照保存有界原始字节、SHA-256、来源权限、服务器时间与身份；独立 reviewer 确认具体检查和冻结事件簇。
3. 领取/准备发送的数据库门控约束所有正常调用入口；暂停、过期检查、已知/不确定答案、登记时间资格及剩余请求/封存时间均受约束。局部不合格任务留失败分母。
4. BLS 草稿使用实际日历/目标 JSON，NOT_FOUND 仅表示该快照未发现；发布族和 UTC 发布时间跨序列共享事件簇。
5. 角色分离、私有 secret-file 注入、默认只读本机工作台、模型 profile 显式启用、有界恢复/封存、日志预算预警和未知费用提示。
6. 前向迁移 0012/0013，不改写历史迁移；工作台显式展示运行类型/赛制/模式。

## 真实失败及修复

- 首轮新数据库测试四处在测试 TSA 的签名精度上界尚未过去时领取任务，按规则被拒绝。修正测试等待实际 upper_time，不放宽门控；新增检查过期、暂停锁等待、已知答案不被好快照清除等回归。
- 第一版 Compose web 只接 internal 网络，宿主映射不可达。添加仅 web 使用的边缘桥接，仍只发布 127.0.0.1，数据库未公开；之后容器启动、中断恢复和还原演练通过。
- 实际 Chromium 检查发现通用表格隐藏嵌套 spec，FIXTURE 类型未展示。通过 0013 追加明确列，保留失败断言，增加数据库标签测试，并逐页面等待各自 HTTP 响应；浏览器复测通过。
- 原供应商测试继续使用合成响应，只显式登记为 DIAGNOSTIC，没有删除旧断言或将其转换成真实 API 验收。

历史失败保留在 Actions。本报告不以新增代码或测试数量代替实际业务能力。
