# ADR-011：问题账本的持久化与准入边界

日期：2026-11-16。范围：P0-01，不改变 V2.0.1 的产品方向。

1. 问题定义从草稿起就是追加式记录。修改内容创建新版本并重新审核；不会把旧版本的审核批准自动带给新版本。
2. 业务写入使用最小授权 PostgreSQL 函数，应用登录不能直接写表。作者/审核/来源许可登记使用独立身份；数据库 owner 仍属于信任边界，不能称为绝对防篡改。
3. 来源许可绑定具体版本及主/备优先级。审核与冻结重新验证当前有效性，之后的采集/推理/公开仍须另行验证，不能把“冻结时许可有效”等同于永久获权。
4. 许可准入只接受 READ COMMITTED。先锁住全部来源再统一检查有效期、撤销和替代情况。0002 为新增前向迁移，不改写已执行 0001。
5. 内容快照包含定义、身份/版本、来源许可绑定；对保存的精确 UTF-8 字节做 SHA-256。它不是 RFC3161、OTS 或结果已知前的时间证明。
6. 本批完成 PostgreSQL 持久化、版本和许可准入验证。原 P0-01 的“真实发布值按修订口径处理”和“多个模型使用同一结果”是跨阶段验收：本批固定口径与问题版本身份，端到端结果行为在 P0-05 验收；不可提前记为完成。
7. 当前没有 HTTP 用户身份映射或部署账号发放系统。后续 API 必须保留这些数据库身份/权限边界，不能用一个超级账号加前端按钮隐藏来替代。

后续依赖：P0-02 的实验任务绑定 version_id；P0-05 的结果和版本化重算绑定同一 version_id。
